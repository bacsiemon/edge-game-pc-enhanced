# Research Notes (All Investigations So Far)

## 1. D3D9 Color / Material Transform Bug (`patches/d3d9_color_fix.py`)
- **Symptom**: Prisms, moving platforms, and finish-area rainbow tiles failed to cycle colors (appearing stuck on white/grey), often triggered when frame overlays such as RTSS interacted with Direct3D 9 after `Present()`.
- **Root cause**: `Material::apply` (`0x437388`) set texture transform matrices (`IDirect3DDevice9::SetTransform(D3DTS_TEXTURE0 + stage, &mat)`), relying on `D3DTSS_TEXTURETRANSFORMFLAGS = D3DTTFF_COUNT2 (2)` remaining intact on stages `0..7`. If external overlays modified or reset `TEXTURETRANSFORMFLAGS`, texture coordinate animations stopped advancing.
- **Fix**:
  - `helper1` (`0x5765b0`) runs the original `SetTransform` and explicitly sets `D3DTSS_TEXTURETRANSFORMFLAGS = 2` on that texture stage.
  - `helper2` (`0x5765d0`) restores `D3DTSS_TEXTURETRANSFORMFLAGS = 2` across stages `0..7` in `Renderer::beginScene` (`0x405f03`).

## 2. Bonus Levels Community Check (`patches/bonus_levels_unlock.py`)
- **Symptom**: Bonus levels gated behind Steam Community group membership remained locked intermittently even after joining.
- **Root cause**: Function `0x4944d0` checked the level-index bounds (`0x4a45d0`) and then returned `BYTE PTR [ecx+0x2d4]` at `0x49450e` (populated asynchronously by Steam group enumeration).
- **Fix**: After bounds checking passes, `0x49450e` unconditionally sets `al = 1` (`mov al, 1; nop*4`).

## 3. UI Scaling, INI Float Config, & Sharp Fractional Fonts (`ui_scale_core.py`, `ui_rt_sharpening.py`, `ui_scale_menu_ini.py`)
- **UI/3D Separation**: 3D scene render targets and particles remain at full physical resolution (`0x407e90` / `0x407ea0`), while 2D camera, viewport, scissor rects, `ScreenMgr` extents, and `MouseController` coordinates use virtual resolution (`0x405b30` / `0x405b60`).
- **Scaling Math**:
  - `ui scale` (`0.1` .. `10.0`, default `1.0`): read from `settings.ini` `[graphics] ui_scale` (values `<= 0` or `< 0.1` clamp to `0.1`; `> 10` clamp to `10`). Clicking in Options cycles presets `[0.5, 0.75, 1, 1.25, 1.5, 1.75, 2, 3, 4]`. (Note: the active C++ DLL in `dll/mod_ui_scale_rt.cpp` uses presets `[0.5, 0.75, 1, 1.25, 1.5, 1.75, 2, 2.25, 2.5]` clamped to `0.1` .. `2.5`.)
  - `auto scale` (`off` / `on`, default `on`, optional INI `[graphics] ui_auto_scale = true/false`):
    - **`on`**: `virtH = round(720.0 / scale)` (`720p` baseline, adapting across resolutions; `scale = 1` yields `720px` virtual height = `200%` on `1440p`).
    - **`off`**: `virtH = round(physH / scale)` (fixed scale multiplier independent of resolution).
  - Virtual height is clamped to `[450, 32768]` so `OptionsMenu` never overlaps vertically while still allowing zoomed-out INI scales (`< 1.0`). With `"credits"` moved out of `OptionsMenu` onto `MainMenu` (`row 3`, replacing `"more games"`), `OptionsMenu` matches `PauseMenu` Page `1` (`12` rows `0..11`).
- **Fractional Font Line-Thickness Fix (`ui_rt_sharpening.py`)**:
  - When `physH % virtH != 0` or `physW % virtW != 0` (such as `125%` or `150%` scaling), direct nearest-neighbor glyph placement causes uneven vertical/horizontal strokes.
  - `begin2D_tail` (`0x4077ae`) and `end2D_hook` (`0x406693`) allocate an integer supersampled 2D `IDirect3DTexture9` render target (`K * virtW x K * virtH`, skipped cleanly if exact integer ratio or `> 4096px`), maintain separate alpha blending via `syncSepAlpha` (`0x405956`), and composite to the physical backbuffer with bilinear filtering (`D3DTEXF_LINEAR`).
- **Save Migration & Standalone Config**: Mod settings are stored in `%LocalAppData%\Two Tribes\EDGE\edgemod_settings.ini` (`[edgemod]` with `schema_version = 1`, locale-independent ASCII parsing/formatting, and atomic `.tmp` + `MoveFileExW` saves) so adding or changing mod options never touches `local_savedata.ttsav` or `Json::Value` serialization (`0x4926e7` `hk_saveTtsav` removed; `Game_SaveUserSettings` reserved strictly for vanilla settings). On startup, `hk_loadUserSettingsLocal` (`0x492ef6` inside `LoadUserSettings` `0x492ed0`) loads/initializes mod settings even if `local_savedata.ttsav` is absent or malformed, migrating any legacy `local_savedata.ttsav` keys captured once at `0x492558` (`hk_loadTtsav`) when `edgemod_settings.ini` does not yet exist. Edits in `settings.ini` (`ui_scale`, `ui_auto_scale`, `camera_distance`, `camera_fov`) still override saved choices on the next launch via `ui_scale_ini` / `ui_auto_ini` / `cam_dist_ini` / `cam_fov_ini`.

## 5. Orthographic / Dolly Camera FOV & Camera Distance (`patches/camera_angle.py`)
- **Symptom**: PC's `22.0` deg perspective camera produces foreground foreshortening and steeper upper-screen angles compared to Mobile EDGE (`v2.2.0`), where the default camera (`use_def == 1`) renders using pure orthographic projection (`M_ortho`).
- **Root Cause & Fix**:
  - Added two independent settings to Main Options (`10` rows `0..9` alone), Pause Menu Page `1` (`10` rows `0..9` alone), `settings.ini` (`[graphics] camera_distance` & `camera_fov`), and `edgemod_settings.ini` (`cam_dist` / `cam_fov`, migrated from legacy `local_savedata.ttsav` `camDist` / `camFov`):
    - **`camera distance`** (`row 7`, `gCamDist` at `0x5fa810`): cycles `[mobile, 0.5, 0.65, 0.75, 1, 1.25, 1.5, 2]` (`1` = PC default) and accepts `mobile`, `pc` (`1`), or any `[0.1, 10.0]` float in `settings.ini`. `mobile` computes `d_eff = clamp(0.01733744 + 0.11558293 * aspect, 0.19071183, 0.26699657) / (max(aspect, 1.0) * tan(11 deg))`.
    - **`dolly zoom`** (`row 8`, `gCamFov` at `0x5fa800`, INI `camera_fov`, save `camFov`): cycles `[pc, mobile, 0, 5, 10, 15, 20, 25, 30]` (`40`, `50` also included in C++ DLL `g_fovPresets[11]`) and accepts `pc` (`-1.0`), `mobile` (`-2.0`), or any `[0.0, 90.0]` float in `settings.ini`.
  - In `camFovVertigoHook` (`0x47ba3b`), when in active gameplay (`[Game+0x2120] != 0` and `[GameEngine+0x50] >= 0x11`):
    - `g_Level` singleton at `0x5f9040` (`[g_Level+0x78] == 568`) identifies `level568` (`"curious land"`), where inverted `22.0` deg triggers stay `35.0` deg in `mobile` FOV mode or `22.0` deg otherwise, while non-`568` `22.0` deg defaults map to `0.0` deg (`mobile`) or `gCamFov` (`0` deg or authored `<= 0` triggers also map to `0.0` deg; perspective values clamp to `[0.5, 90.0]`).
    - `pc` FOV (`-1.0f`) uses stock `0x481c50` (`GetVertigo(fovy)`) when `vertigo != 0`, multiplied by `d_eff`.
    - **True Orthographic (`DLL`, `preAspectFov < 0.25` deg — `mobile` default, `0` deg, and authored `<= 0` isometric triggers such as `level568`'s `-1`)**: `CamFovVertigo_Impl` passes sentinel `0.01` deg (`fovy_rad <= 0.0005`) and `kOrthoDistBoost = 16.0f` distance multiplier; `PerspScaleY_Impl` (`0x4357f7`) replaces the projection matrix via `D3DXMatrixOrthoRH` (`0x4bb2ca`, applying Mobile `1.65 / 1.55` Y stretch when `g_camFov == -2.0f` and keeping `[cam+0x2b0] == 1` so `Camera::worldToScreen` `0x423080` stays intact) for zero parallax error on Escher illusions; `FrustumSetFov_Impl` (`0x435750`) sets `frust[0] = 100.0f` to avoid perspective-frustum culling; `hk_edgeTimeTanHalfFov` (`0x47b826`) and `hk_panTanHalfFov` (`0x495659`) supply effective `(ComputeDeff(aspect) * tan(11 deg)) / 16.0f` so the floating `"EDGE TIME"` counter and Pause/Win screen-to-world camera pan remain properly scaled; and `AdjustNearFar_Impl` (`0x47bbc3`) brackets `[max(10, dist - 8000), dist + 8000]` for `~0.00095`-unit linear D24S8 depth precision.
    - `mobile` FOV (`-2.0f`) perspective zones (`> 0` deg, e.g. `level568`'s `35.0` deg triggers) lock horizontal FOV (`fovy = 2 * atan(tan(fov_x / 2) / aspect)` for `aspect > 1.0`), apply Mobile `1.65 / 1.55 = 1.06451613f` projection Y-stretch at `0x4357f7` (`perspScaleY`), and apply dolly multiplier `d_eff * tan(11 deg) / tan(fov_eff / 2)` (with `10` deg horizontal fallback for non-vertigo custom perspective zones).
    - Numeric `0.5..90` deg FOV keeps `1.0x` projection Y-aspect (`perspScaleY` untouched), uses `d_eff * tan(11 deg) / tan(fovy / 2)` for dolly zoom (`vertigo != 0` or `fovy <= 1.0`), and `d_eff` for custom non-vertigo perspective zones.
    - **Transition Continuity & `vertFlag` Blending (DLL)**: `hk_setFov` (`0x481bb0`, `ScreenMgr::setFov`) captures the previous rendered `preAspectFov` and dolly constant `K` so mid-transition re-triggers and `ws + 0xe0` win outros continue smoothly from the current rendered state instead of snapping, `CamFovVertigo_Impl` linearly interpolates `K` across `vertFlag` changes (`curK / tan(fovy / 2)`), and `OnInterpolate_Impl` guards against single-tick ortho ↔ perspective mismatches across `camBuf[prev]` / `camBuf[cur]`.
  - **Shadow Z-fighting fix (`Block H`: `saveActiveMul` at `0x47ba5f`, `adjustNearFarHook` at `0x47bbc3`)**: Stock EDGE scales both `near` (up to `900.0`) and `far` (`~11,000 * mul`) linearly with `mul`. At `mobile` / `0` deg telephoto FOVs (`mul = 28.8..44.5`), linear scaling spreads 24-bit D24S8 depth across `[900, 395k..490k]`, raising `1` depth quantum at the cube (`0.044..0.055` units) past EDGE's `0.001 * 30 = 0.030`-unit `ShadowVolume` prism inset and causing Z-fail stencil shadows to flicker.   - **Skybox projection & frustum fix (`Block H2`: `skyboxProjWrap` at `0x4234d0..0x4235e0`, hooking `0x407805`)**: `skybox_1..4.rmdl` (`[Renderer+0x58]`, scaled `30.0f` at `cam_eye`) places the glow dome `Sub[0]` at world radius `1108.57` and stars `Sub[1]` at `1018.92`, with root bounding sphere `R = 1920.09`. `adjustNearFarHook` shifting `near` toward/past `1018.9..1920.1` causes (1) GPU near-plane slicing/clipping of `Sub[0]`/`Sub[1]` (making the glow dome visibly shrink into a sphere/disc before vanishing), (2) CPU `Frustum::testSphere` (`0x4356a0`) culling `SkyRoot` at `near > 1920.09`, and (3) `< 22` deg / `mobile` FOV zooming into a narrow cap. `skyboxProjWrap` wraps `Renderer::renderSkybox` (`0x4075f0`) with a stack `D3DMATRIX` (`fovy = max(cam->fovy, 22 deg)`, `near = 100.0`, `far = 8000.0`) and temporary `Camera+0x30c` `Frustum` (`tan = 1.0`, `far = 8000.0`, `near = 100.0`), then restores both `Frustum` and `D3DTS_PROJECTION` (`[edx+0x304]`).

## 6. Customizable Music & SFX Volume (`patches/audio_volume.py`)
- **Symptom**: Stock `OptionsMenu` and `PauseMenu` Page `1` only toggle `sounds` and `music` between `off` (`0`) and `on` (`100`) even though `UserSettings` (`ScreenMgr + 0x2ac/+0x2b0`) and `local_savedata.ttsav` (`musicVolume`/`sfxVolume`) already store integers `[0, 100]`.
- **Root Cause & Audio Engine Fix**:
  - `AudioPlayer` (`0x5f903c`) references XACT category `"Effects"` at `0x585474`, whereas `audio/edge.xgs` defines only `Global`, `Default`, and `Music`, and all 165 SFX sounds in `audio/sfx.xsb` belong to `Default`. Replacing `0x585474` with `"Default\0"` enables `AudioPlayer::setVolume(0, sfxVol / 100.0f)` (`0x474480`) to attenuate all XACT SFX cues cleanly.
  - `scaleMusicVol` (`0x4744a3`) scales channel `1` (`OggStream`) gain by `vol * 0.75 * clamp(musicVolume, 0, 100) / 100.0` so music fades, ducks, and live step adjustments respond smoothly without restarting the active track (`0x481780` runs only on `0 -> >0`).
  - `applyVolOnLoad` (`0x482b7f`) clamps loaded `[0, 100]` values and applies SFX volume (`0x474480(0, ...)`) and initial `0.0f` music gain immediately after `loadUserSettings` (`0x492ed0`).
  - `stepVol10` steps `[0, 100]` in increments of `10` (Left wraps `0 -> 100`, Right/Enter/Click wraps `100 -> 0`) and `fmtInt0to100Wstr` renders numeric `"0".."100"` in both Main Options and Pause Menu Page `1`. (The active C++ DLL replaces toggles/steps with interactive `0..100` sliders stepping by `5` on Left/Right with hover SFX `2` on value changes.)
  - **Mute When Unfocused (`0x44d72f` -> `hk_GameWndProc`, `mute_unfocused`)**: Subclassing the window procedure pointer pushed at `0x44d72e` (`KeyboardWndProc` `0x44d4e0`) tracks `WM_ACTIVATEAPP`, `WM_ACTIVATE`, `WM_SETFOCUS`, `WM_KILLFOCUS`, and `WM_SIZE` (`SIZE_MINIMIZED`) even when DXUT pauses `FrameMove`. When `g_muteUnfocused != 0` and the window is unfocused/minimized, `SyncFocusAudioMute()` drives XACT `"Default"` volume to `0.0f` in `ApplySfxVolume` and forces `CalcScaledMusicVol` (`0x4744a3`) to return `0.0f` (also keeping `[OggStream+0x4]` muted on track transitions).
